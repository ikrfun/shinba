# Vim 操作とキーバインドの設計案

この文書は検討用の案です。まだ実装していません。

## 最初の対象

Monaco のコード編集領域で Vim 操作を使えるようにする。エディターを開いたときは Normal モードとし、現在のモードを表示する案とする。

- Normal モードで `h`、`j`、`k`、`l` によってカーソルを移動する。
- Normal モードの `i` で Insert モードに入る。
- Insert モードの `Esc` または `Ctrl+[` で Normal モードに戻る。
- Vim 操作の有効・無効を切り替えられるようにする。

矢印キー、テキスト入力、IME、ファイル切り替え後の状態も実機で確認する。キーボード配列によって `Ctrl+[` を入力できるかは環境ごとに確認する。

## 入力を受け取る場所

エディターにフォーカスがあるときだけ Vim 操作を適用する。ターミナルではシェルや実行中の CLI が入力を受け取り、WB のカード編集欄と設定画面では通常のテキスト入力を維持する。WB 自体のショートカットは別に設計する。

## 実装候補

Monaco 向けの `monaco-vim` を試す。Monaco のインスタンスに取り付け、無効化時やエディターの破棄時に解除する。モード表示には専用のステータス領域を使う。対象の Monaco バージョンとの互換性、キー競合と IME の挙動を確認して採用を判断する。

`monaco-vim` は Vim の操作を模倣する部品であり、実際の Vim や Neovim を起動するものではない。対応する操作や設定が完全に同じとは限らない。

## 設定の扱い

最初はアプリ全体の個人設定として、Vim モードの有効・無効だけ保存する案とする。設定画面から変更し、プロジェクトごとに共有する `.shinba/` には置かない。保存場所は Electron のユーザーデータ領域を候補とする。初期値は未決定。

独自のキー割り当てが必要になった段階で、設定ファイルや設定画面を検討する。既存の Vim 設定ファイルを読み込むことや、任意の Vim スクリプトを実行することは、現時点では対象に含めない。

将来の設定形式の例。これは提案であり、実装済みではない。

```json
{
  "editor": {
    "vim": { "enabled": true }
  }
}
```

## キー競合と確認

モードとフォーカスを条件に扱い、アプリ全体、エディター、ターミナルのショートカットが競合する場合は、対象となる領域を明確にする。F12 の定義ジャンプ、保存、コピー＆ペースト、検索と Vim コマンドの扱いは試して決める。

次を確認する。

1. `hjkl` の移動と `i`、`Esc`、`Ctrl+[` のモード切り替え。
2. 日本語入力中の `Esc` とモード表示。
3. ファイル切り替え、Vim の有効・無効切り替え、エディターの再作成時の挙動。
4. WB のテキスト欄とターミナルで Vim キーを横取りしないこと。
5. 既存の自動保存と定義ジャンプが使えること。
